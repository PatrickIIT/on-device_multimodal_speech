# on-device_multimodal_speech
# Hardware-Aware Compression of Streaming Speech Models for Low-Resource Android Devices

## Status

**Research in progress — experimental results are not yet available.**

---

## Abstract / Project Summary

This project investigates principled methods for compressing and deploying streaming Automatic Speech Recognition (ASR) models on resource-constrained Android mobile devices, with an empirical focus on the **Swahili (Kiswahili)** language and real-device execution on the **Samsung Galaxy A13**.

Deploying state-of-the-art speech models on edge hardware requires navigating severe trade-offs among acoustic recognition accuracy, compute latency, peak memory consumption, and thermal/energy dissipation. This research systematically studies:
* **Quantization** (FP16, INT8, INT4 post-training and quantization-aware training),
* **Structured Pruning** (channel, attention-head, and layer-level sparsity),
* **Knowledge Distillation** (cross-architecture teacher-student loss formulations),
* **Streaming Acoustic Configuration** (causal chunking and voice activity detection windows),
* **Hardware-Aware Model Selection** (multi-objective constrained search tailored to low-end mobile SoCs),
* **Offline On-Device Android Inference** (ONNX Runtime, ExecuTorch, and embedded streaming runtimes).

---

## Research Question

> **How can we jointly optimize model compression and streaming configuration to preserve speech recognition quality while reducing latency, memory, and energy consumption on low-resource Android devices?**

---

## Research Philosophy

### What this project is NOT
* It is **not** simply "running Whisper on a phone".
* It is **not** only an INT8 vs. INT4 benchmark comparison.
* It is **not** a generic conversational chatbot application.
* It is **not** a premature claim that the proposed method is already state-of-the-art.
* It is **not** a collection of fabricated benchmark numbers or simulated measurements.

### What this project investigates
> **Whether hardware-aware selection of compressed streaming speech models can provide a systematically superior quality-efficiency trade-off on resource-constrained Android devices.**

## Target Hardware

* **Primary Target Device**: Samsung Galaxy A13 (SM-A135F / SM-A137F)
  * **SoC**: Samsung Exynos 850 (8x ARM Cortex-A55 @ 2.0 GHz) or MediaTek Helio G80
  * **RAM**: 3 GB / 4 GB LPDDR4X (severe memory pressure under background OS tasks)
  * **OS**: Android 12 / 13 / 14
  * **Environment**: Termux / CLI environment for automated empirical benchmarking, followed by a standalone on-device runtime application.
* **Secondary / Comparative Hardware**: Potential additional low-resource Android devices to be integrated in future evaluation phases.

## Datasets

The research framework is built around public speech corpora and carefully structured out-of-domain evaluation sets:

* **Common Voice Swahili (Mozilla)**: Main ASR training, validation, and in-domain evaluation corpus.
* **FLEURS Swahili (Google)**: Multi-domain cross-dataset evaluation to evaluate generalization error across recording acoustic profiles.
* **Speech Commands (Swahili adapted / multilingual)**: Controlled lightweight streaming experiments and keyword/intent baseline testing.
* **Noisy Evaluation Sets**: Synthetic evaluations generated by mixing evaluation splits with real environmental background noise at specified Signal-to-Noise Ratios (SNRs).
* **A13 On-Device Recordings**: Small out-of-domain calibration and device-condition evaluation set captured directly via the Samsung Galaxy A13 microphone hardware in varied real-world acoustic settings.
  * *Note: Device recordings serve purely as supplementary ecological validation and will NOT replace standardized public benchmark test splits.*

## Proposed Research Direction: Hardware-Aware Selection

```text
Candidate Configurations (Quantization × Sparsity × Chunk Size)
        ↓
Evaluate Quality (WER, CER)
        ↓
Evaluate Latency (Mean, Median, P50, P90, P95 ms)
        ↓
Evaluate Memory (Peak RSS, PSS RAM MB)
        ↓
Evaluate Energy (Battery Drain Wh, Thermal State)
        ↓
Apply Hardware Constraints (RAM < R_max, Latency < L_max)
        ↓
Select Feasible Configuration (Pareto-optimal trade-off)
```

### Research Formulation (Under Investigation)

The candidate configuration selection objective is formalized as a constrained multi-objective optimization problem:

$$\min_{\theta \in \Theta} J(\theta) = \text{WER}(\theta) + \lambda_1 \cdot \text{Latency}(\theta) + \lambda_2 \cdot \text{RAM}(\theta) + \lambda_3 \cdot \text{Energy}(\theta)$$

$$\text{subject to:} \quad \text{RAM}(\theta) \le R_{\max}, \quad \text{Latency}(\theta) \le L_{\max}, \quad \Delta\text{WER}(\theta) \le \epsilon_{\max}$$

*Disclaimer: This formulation is an empirical research hypothesis under active investigation, not an established closed-form algorithm.*

## Evaluation Metrics

### Speech Recognition Quality
* **Word Error Rate (WER)**: Standard token-level Levenshtein edit distance normalized by reference word count.
* **Character Error Rate (CER)**: Character-level Levenshtein edit distance for phonetic and morphological error analysis in Swahili.

### Computational & Hardware Efficiency
* **Model Size**: Total disk footprint in Megabytes (MB).
* **Parameter Count**: Total and active non-zero trainable parameters.
* **FLOPs / MACs**: Theoretical floating-point operations per second of speech.
* **RAM Footprint**: Peak Resident Set Size (RSS) and Proportional Set Size (PSS) in Megabytes (MB).
* **CPU Utilization**: Percentage utilization across efficiency (Cortex-A55) cores.
* **Inference Latency**: Distribution across cold-start, warm-start, mean, median, p50, p90, and p95 latencies (ms).
* **Real-Time Factor (RTF)**:
  $$\text{RTF} = \frac{\text{Inference Time (seconds)}}{\text{Audio Duration (seconds)}}$$
  An $\text{RTF} < 1.0$ indicates execution faster than real-time.
* **Energy Consumption**: Battery discharge energy (Watt-hours / milliampere-hours) over sustained streaming sessions.
* **Thermal State**: SoC thermal throttling indicators and temperature deltas during continuous decoding.

## Streaming & Noise Studies

### Streaming Acoustic Chunk Sizes
* **100 ms**: Ultra-low latency edge configuration
* **200 ms**: Low-latency interactive configuration
* **400 ms**: Balanced baseline streaming configuration
* **800 ms**: High-context streaming configuration

* **Acoustic Environments**: Clean, Traffic, Office, Crowded Babel/Babble, Cooling Fan, Wind, Background Music.
* **Signal-to-Noise Ratios (SNRs)**: Clean ($\infty$), $20\text{ dB}$, $10\text{ dB}$, $5\text{ dB}$, $0\text{ dB}$.

## Initial Model Strategy

The project prioritizes incremental, verifiable milestones:
1. **Milestone 1**: A lightweight streaming ASR architecture suitable for real-time edge execution (e.g., streaming Conformer / Emformer / Zipformer or small distilled Whisper variant) evaluated on Swahili.
2. **Milestone 2**: Systematic compression and on-device deployment benchmarking on Samsung Galaxy A13.
3. **Milestone 3**: Integration of an edge Small Language Model (SLM) for spoken intent/multimodal understanding.
